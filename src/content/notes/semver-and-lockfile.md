## 语义化版本 semver

版本号 `MAJOR.MINOR.PATCH`，含义是一种**承诺**：

| 段 | 何时 +1 | 含义 |
|---|---|---|
| MAJOR | 破坏性变更 | 升级可能要改你的代码 |
| MINOR | 新增功能、向后兼容 | 加了东西，旧用法不受影响 |
| PATCH | 修 bug、向后兼容 | 只修不改 |

`package.json` 里的范围符决定**允许自动升到哪**：

```jsonc
"react": "^18.2.0"   // ^ 锁主版本：允许 18.x.x 里最新的（最常用）
"react": "~18.2.0"   // ~ 锁次版本：只允许 18.2.x
"react": "18.2.0"    // 锁死：只装这个确切版本
```

## lockfile：把"范围"钉成"确切"

`^18.2.0` 是个范围，今天装是 18.2.0，下个月别人装可能就是 18.3.1 了。**lockfile（`package-lock.json` / `pnpm-lock.yaml`）记录整棵依赖树每个包解析出的确切版本**，保证任何人、任何时间、任何机器装出来的完全一致。

> "在我机器上是好的"——很大一部分这类玄学，根源就是没提交 lockfile，大家装到了不同的版本。

## 纪律

- **lockfile 必须进 Git**，它和源码一样是项目的一部分。
- CI 用 `npm ci`（严格照 lockfile 装、对不上就报错），不要用 `npm install`（可能悄悄改写 lockfile）。
- 升级依赖是一次**主动、可审查**的动作（改 lockfile + 跑测试），不该是某次安装的副作用。
