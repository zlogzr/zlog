详情页上选颜色、选尺码的那个组件，看着简单，做对不易。核心需求：**用户每选一个值，其他属性里「凑不出在售 SKU」的值要自动置灰**，避免用户辛苦选完才发现没货。

## 问题定义

给定：所有在售 SKU（属性组合的子集）+ 用户当前已选的部分属性。求：每个属性的每个值，**是否应该可点**。

判定规则：

> 属性 A 的值 `v` 可点 ⟺ 存在一个在售 SKU，它在 A 上取 `v`，且在**其他已选属性**上与用户的选择一致。

换句话说：把 `v` 代入「当前已选 + 这个 v」，看还能不能匹配到至少一个真实 SKU。

## 算法

```js
// skus: [{ id, attributes: {颜色:'红', 尺码:'M'}, stock }]
// selected: 用户已选，如 { 颜色: '红' }（尺码还没选）

function isValueAvailable(skus, selected, attrName, value) {
  // 构造“假设选了这个值”的条件：已选项里去掉当前这一维，再加上 value
  const cond = { ...selected, [attrName]: value };
  return skus.some(sku =>
    sku.stock > 0 &&
    Object.entries(cond).every(([k, v]) => sku.attributes[k] === v)
  );
}

// 渲染每个属性的每个值时调用，决定是否置灰
// 注意：判断某个值时，要把“它自己这一维”从 selected 里排除掉，
// 否则你已选的“红色”会让其他颜色全部判为不可选。
```

关键细节：**判断「颜色」这一维的各个值时，selected 里不能包含「颜色」的当前选择**——否则会拿旧的颜色去过滤，把其他颜色全判死。正确做法是「其他维固定、当前维放开试」。

## 性能：预计算邻接关系

SKU 多时，每次渲染都全表 `some` 会卡。优化是**预计算**：把「每个属性值 → 包含它且有货的 SKU 集合」建成索引，判断可选性变成集合求交：

```js
// 属性值 → 拥有该值的有货 SKU id 集合
// 值 v 可选 ⟺ (其他已选维各自的集合 ∩ v 的集合) 非空
```

集合用 bitset / `Set` 实现，交集很快，几百上千 SKU 也流畅。

## 交互上的取舍

- **置灰 vs 隐藏**：通常**置灰**（保留位置、可点出提示「该组合无货」）比直接隐藏好——隐藏会让布局跳动，用户也不知道发生了什么。
- **允许「反选」**：已选「红色」后，红色本身要能再点一下取消，回到「未选颜色」状态重新组合。
- **唯一可选自动选中**：某属性只剩一个可选值时，可自动帮用户选上，减少点击。
- **缺货也要可选 + 提示**：有时希望用户能选到「无货组合」并显示「到货通知」，而不是死灰一片——这是产品决策，算法上对应「`stock > 0` 这个条件要不要加」。

## 结论

规格选择器 = 「在售 SKU 子集」上的一个可达性查询：固定其他已选维，看当前维的每个值还能不能凑出真实有货的 SKU。数据结构（见「销售属性与笛卡尔积」的 skuMap）打好了，这个算法就十几行。难点不在代码，在那些边界：排除自身维、反选、唯一项自动选、缺货提示。
